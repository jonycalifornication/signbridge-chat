# signbridge-chat — генератор видео с жестовым переводом

Отдельное приложение: текст на входе, готовое видео с сурдопереводом на выходе.
Крутится на сервере с GPU, потому что рендер видео — тяжёлый.

Аватар этому проекту **не принадлежит**. Аватар — продукт проекта
`signBridge-avatar`, который живёт на другом сервере (без GPU) и подключается к
сайтам клиентов. Правки аватара всегда делаются там. Здесь его код не копируется
и не редактируется.

## Как это устроено

```
Браузер ──► nginx (порт 5173) ──► index.html = видеогенератор
              │
              ├─ /api/v1/video/*   ─┐
              ├─ /api/v1/sessions  ─┼─► рендерер (Node, порт 3003)
              └─ /admin/*          ─┘        │
                                             │  puppeteer + WebGL на GPU
                                             │
                                             ├─► ЗЕРКАЛО аватара (локально)
                                             │   /avatar/current/embed.html
                                             │   + внедряемый src/headless/inject-renderer.js
                                             │
                                             ├─► план жестов: 1 запрос в
                                             │   widget.signbridge.kz/api/v1/translate/
                                             │
                                             └─► VRMA-файлы: напрямую из хранилища
```

Ключевая идея: рендерер открывает **страницу аватара** и внедряет в неё свой
скрипт. Аватар владеет воспроизведением — глоссы, склейка двух клипов на жест,
скорость, липсинк и дактиль живут в его `playTranslateResponse()`. Мы его
вызываем, а не переписываем. Text→gloss тоже его: gateway сам обращается к
сервису t2g внутри `/translate/`. Вся логика видео
(виртуальное время, захват кадров, кодирование) остаётся здесь.
Наследования от кода аватара нет — только вызовы его API.

### Зеркало аватара

Собранные файлы аватара копируются на этот сервер, и рендер идёт из копии:

* продуктовый сервер не получает ни рендер-нагрузки, ни трафика анимаций;
* его недоступность или деплой не ломают генерацию видео;
* новая сборка аватара сначала проверяется и только потом становится живой.

Обновление: скачать в `candidate/` → прогнать настоящий короткий рендер →
атомарно переключить на `current/`. Если рендер не прошёл — остаётся прежняя
версия, а причина уходит в лог. Прошлая версия лежит в `previous/` для отката.

```bash
npm run avatar:sync                                # первичная загрузка (без проверки)
curl -X POST localhost:3003/admin/avatar/sync      # обновить с проверкой
curl -X POST localhost:3003/admin/avatar/rollback  # вернуть прошлую версию
curl localhost:3003/admin/avatar/status            # что сейчас живое
```

Автообновление по расписанию — `AVATAR_SYNC_INTERVAL_MS` (минимум 60000 мс).
Каждое обновление проходит ту же проверку рендером.

## Запуск

```bash
cp .env.example .env    # заполнить AVATAR_API_KEY
docker compose up -d --build
```

С GPU:

```bash
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d --build
```

Локально без docker:

```bash
npm install
npm run avatar:sync     # положить аватара в зеркало
npm run server          # рендерер на :3003
npm run dev             # UI на :5173
```

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `AVATAR_URL` | откуда берётся сборка аватара. Читается **только** при синхронизации зеркала |
| `AVATAR_API_KEY` | наш клиентский ключ для gateway аватара. Расход считается по ключу — нужен свой, не мастер-ключ виджета |
| `AVATAR_FILES_URL` | хранилище, откуда качаются VRMA. Напрямую, минуя продуктовый сервер |
| `AVATAR_SYNC_INTERVAL_MS` | автообновление зеркала; пусто = только вручную |
| `RENDER_PLAN_LANGUAGE_ID` | код языка. Бэкенд знает `KSL`, `RSL`, `ASl` — не `kz_KSL` |
| `PORT`, `SELF_URL` | порт рендерера и то, как puppeteer до него дотягивается |

## Что где лежит

| Путь | Что это |
|---|---|
| `index.html`, `src/video-generator/` | UI видеогенератора, он же корень сайта |
| `src/server/index.js` | рендерер: очередь, puppeteer, кэш, ключи, сессии |
| `src/server/avatar-mirror.js` | скачивание, проверка и переключение зеркала аватара |
| `src/headless/inject-renderer.js` | то, что внедряется в страницу аватара. Без импортов, без сборки |
| `src/headless/render-plan.js` | один запрос в gateway + предпросмотр глосс и оценка таймаута |
| `avatar_mirror/` | копия сборки аватара (в git не хранится) |

## API рендерера

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/v1/video/generate` | синхронно, отдаёт webm телом ответа |
| `POST` | `/api/v1/video/generate-async` | ставит задачу, возвращает `taskId` |
| `GET` | `/api/v1/video/status/:taskId` | SSE с прогрессом |
| `GET` | `/api/v1/video/download/:taskId` | готовый файл |
| `POST` | `/api/v1/video/preview` | только предпросмотр глосс, без рендера |
| `GET/POST` | `/api/v1/sessions` | история чатов |
